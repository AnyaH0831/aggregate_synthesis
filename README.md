# aggsyn: what can published aggregate tables support?

Public social-service data is usually published only as **aggregate tables** (counts). This repository studies how well you can
rebuild person-level data from such tables, which tables an agency should publish, and what is lost. It was developed on real
administrative homelessness records (Lanark County) plus four public datasets where the individual rows are known, so every claim
can be checked against ground truth.

**Main claim.** Which tables you publish matters far more than which generator you use. Tables that cross the *outcome* with each
feature carry almost all the usable signal and are also the safest to publish (few tiny cells). The common "keep as much overall
structure as possible" rule is no better than random for prediction at small budgets. 

## Headline results (all numbers regenerated by `analysis/summarize.py`, see `results/SUMMARY.md`)

| Result | Evidence |
|---|---|
| Totals alone carry no outcome signal; outcome x feature tables recover almost all of it | E00: AUC of a model trained on the implied joint, S1 vs S2 vs real, 5 datasets |
| Task-aware table choice beats the standard choices by about 0.11 AUC (3 tables, n~500, rounded, small cells hidden) | E06: 15 repeats x 5 datasets, 95% CI about +0.09 to +0.14, holds for XGBoost |
| A simple rule (outcome x feature tables ranked by mutual information with the outcome) is as good as the greedy search | E06: difference -0.003, CI covers 0 |
| Range-respecting rounding cuts contradicted published ranges from about 13% to 5% (rounding 5) and 9.5% to 1.5% (rounding 10) at no accuracy cost | E03 |
| Interval fitting (M2) does not generalise; it helps only for very coarse rounding (20) | E02, E03 |
| With a small real sample, synthetic data from the tables helps a lot (+0.05 AUC at n=30) but the gain comes from the tables covering far more people | E07 |
| A pre-release certificate bounds the AUC loss of a table set, valid in 25/25 cases and 2-3x tighter than older bounds | E10 |
| Tables cannot certify subgroup rates: possible range is 0.56-0.87 wide on average | E05 |
| Privacy: the most useful tables have few tiny cells; allowing just 2 tiny cells recovers nearly all utility | E08 |

**Honest limits.** Aggregates are simulated by summarising the individual rows (no real published tables yet). Greedy selection has no
proven guarantee (it matched the exhaustive optimum in every test, E09). The certificate is relative to the best scorer on the same
features and is overstated on tiny datasets. AIM/MST themselves were not run (their code needs an older `mbi`); our information-tree and
greedy are their noiseless analogues. Full list in the report, section 8.

## Layout

```
aggsyn/                 library
  tables.py             TableSpace: tables/margins, IPF (max-entropy), interval fitting M2, controlled rounding (ILP), SASM-like annealing, metrics
  selection.py          which tables to publish: task-aware / task-agnostic greedy, information tree, label-first, random
  certificate.py        pre-release AUC-loss certificate; exact LP bounds on subgroup rates
  metrics.py            entropies, KL, conditional KL, weighted AUC
  datasets.py           loaders for the five datasets
  cli.py                shared command-line options
experiments/            one script per result (E00-E10), each writes a CSV into results/
analysis/summarize.py   turns results/*.csv into results/SUMMARY.md
examples/quickstart.py  end-to-end demo (choose tables -> publish rounded -> rebuild people -> check)
tests/                  unit tests of the theory (naive-Bayes equivalence, entropy-gap identity, chain rule, certificate validity, separation example, LP bounds)
results/                saved outputs of all experiments + SUMMARY.md
docs/RESEARCH_REPORT.md research report: findings, proofs, evidence, literature
run_all.sh              reproduce everything
```

## Data

Raw data are not included. See [`data/README.md`](data/README.md). `mroz` and `gss` need nothing; `adult` downloads itself; `lanark` and
`gss34` need your files in `data/`.
The Census case study uses the supplied 2021 PUMF, keeps Toronto CMA
(`CMA=535`) persons aged 15+ (`AGEGRP` 6--21), treats `LFACT` 1 or 2 as
employed, maps the dictionary's Woman+/Man+ gender codes explicitly, and
ignores sampling weights for this first unweighted analysis.

## Quickstart

```python
from aggsyn import datasets, TableSpace, Selector, population_certificate
d = datasets.load("mroz", "data"); s = TableSpace(d); S = Selector(s)
t = s.table(d); p = t / t.sum()

tables = S.greedy(p, 3, "cond")                    # data holder: which 3 pair-tables to publish
tabs = S.ones + tables                             # single-variable totals are always published
print(population_certificate(s, p, S.fit(p, tabs))["certificate"])   # worst-case AUC loss, computed before publishing

pub = s.publish(t, tabs, 5)                        # rounded to 5, cells below 5 hidden
lo, hi = s.intervals(pub, 5)                       # data user: the ranges consistent with what was published
q = s.m2(tabs, lo, hi, len(d))                     # max-entropy joint inside the ranges (or s.ipf(...) on the numbers)
syn = s.ilp(q, len(d), tabs, lo, hi, interval=True)  # integer people that respect every published range
```

or `python examples/quickstart.py --dataset lanark --data-dir data`.

Every script accepts `--datasets`, `--reps`, `--data-dir`, `--out-dir`, `--quick`. The saved CSVs in `results/` for E03-E08 come from the
original runs of the same logic (before the code was consolidated into the package); E00-E02 and E09-E10 were regenerated with this code.
Small differences from re-running are expected (random splits, solver time limits).

For the Census case study, run the PUMF-built-table versions with:

```bash
python experiments/e06_table_selection_sample.py --datasets census
python experiments/e03_rounding_all_datasets.py --datasets census
python experiments/e04_table_selection_population.py --datasets census
python experiments/e10_auc_certificate.py --datasets census
```

The supplied published Toronto table is a labour-status/age/gender reference
but does not align with the loader's full feature set, so direct published-table
evaluation is a stretch goal.

The small published-table pilot uses only that Toronto CSV for fitting:

```bash
python experiments/census_published_pilot.py
```

It uses disjoint 15--24, 25--34, 35--44, 45--54, 55--64, 65--74 and 75+
bands, checks the `Employed`, `Unemployed`, `Not in the labour force`, and
total rows together under conservative StatCan random-rounding intervals
`[reported - 5, reported + 5]`, and trains on the resulting synthetic rows.
The PUMF is used only for the weighted held-out evaluation and a separate
weighted PUMF-training baseline. Results are written to
`results/census_published_pilot.csv`.

## Known issues

- `ilp` has a time limit; if the solver finds no solution it falls back to an arbitrary rounding, which can inflate the number of contradicted
  ranges (seen once: `M2+intervalILP` on Adult, rounding 5, 26% contradicted). Raise `tl` to check.
- `e06` / `e08` use logistic regression and XGBoost with fixed settings; no tuning.
- The Canadian GSS file is an incident file (rows are crimes, not people).
